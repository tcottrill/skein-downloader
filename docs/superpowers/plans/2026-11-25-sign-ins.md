# Sign-ins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let downloads carry a saved sign-in (password, access token, or archive.org keys) to the server it belongs to, stored in the operating system's credential store and never sent anywhere else.

**Architecture:** A new engine unit, `src/signin.{h,cpp}`, holds the sign-ins in memory, decides which request may carry which one, and builds the header. The HTTP layer attaches it where a request is built and, for such requests only, follows redirects itself so the secret never reaches another host. FTP logs in with it. The window code reads and writes the credential store through `wxSecretStore` and hands the engine a table; the engine never touches the store.

**Tech Stack:** C++20, WinHTTP and WinINet (Windows), libcurl (Linux), wxWidgets 3.3 `wxSecretStore`, CMake/CTest, the Python loopback test server.

**Spec:** `docs/superpowers/specs/2026-11-25-sign-ins-design.md`. Read it before any task; where this plan and the spec disagree, the spec wins.

## Global Constraints

- A secret is never written to `settings.ini`, `history.json`, a staging folder's `state.json`, the log, or a command line.
- A secret is never sent to a host other than one its sign-in covers, including after a redirect. Coverage is by exact host name except the one archive.org rule in the spec.
- Over `http` or `ftp` a password is sent only when its sign-in has `allowUnencrypted`; tokens and archive.org keys are never sent unencrypted. Ruling for this plan: the loopback hosts `127.0.0.1`, `::1` and `localhost` count as encrypted (the data never leaves the machine); this also lets the tests run without TLS.
- No sign-in window opens from a background download.
- Requests to hosts with no sign-in behave exactly as today (same redirects, same errors, same messages), except that a 401 now raises `SignInNeeded`.
- The engine library (`archive_core`) does not include or link wxWidgets.
- Everything builds and passes on Windows and Linux: `cmake --build --preset vs2022-release`, `ctest --test-dir build/vs2022 -C Release --output-on-failure`, and `wsl -e bash -lc "cd /mnt/c/Source2026/skein-downloader && cmake --build build/linux 2>&1 | tail -15 && ctest --test-dir build/linux --output-on-failure 2>&1 | tail -15"`.
- New UI text uses `_(L"...")`; backend messages shown in the window are marked with `wxTRANSLATE()` in `src/wx/localization.cpp`. After adding text: `python tools/translations.py --update`, fill all 12 non-English catalogs in each catalog's existing vocabulary (Portuguese is European), then `python tools/translations.py` and `--check`.
- Native controls and the house rules in `C:\Users\user9\.claude\lessons\wxwidgets-app-standard-setup.md`.
- Tests follow the existing style: one `main`, a failed expectation throws `std::runtime_error` with a sentence naming it. Format C++ with the repository's `.clang-format`. Files are written with editor tools, never shell heredocs.
- Implementers do not commit, push or switch branches. The reviewer commits each task on branch `sign-ins`.

## Review Focus

1. A redirect from a signed-in host to another host: the second host must receive no `Authorization` header (Task 2 test `redirect-out`).
2. A redirect chain that comes back to a covered host: that hop gets the sign-in again, and a loop stops at 10 hops (Task 2 tests `redirect-back`, `redirect-loop`).
3. A multi-connection, resumed download from a server that needs a password: every connection signs in and the file is correct (Task 2 test `basic-ranges`).
4. A wrong password: reported as "not accepted", never retried forever, and the queue does not retry it automatically (Task 2 test `basic-wrong`, Task 7 queue test).
5. After a signed-in download the secret appears in none of: the log, `history.json`, `state.json`, the job's stored input (Task 8).

Not testable by agents, for the owner with real accounts: a gated Hugging Face repository with a token; a private GitHub release with a token; an account-only archive.org item with access keys; the keyring prompt on Linux.

### Task 1: The sign-in table

**Files:** Create `src/signin.h`, `src/signin.cpp`, `tests/signin.cpp`. Modify `CMakeLists.txt` (both `archive_core` source lists), `tests/tests.cmake` (target `signin_tests`, CTest name `signin`, in `skein_warnings`).

**Interfaces — Produces** (namespace `archive`):

```cpp
enum class SignInKind { Password, Token, ArchiveKeys };
struct SignIn {
    SignInKind kind = SignInKind::Password;
    std::string host;            // lower case, as saved: "example.org", "huggingface.co", "github.com", "archive.org"
    unsigned port = 0;           // 0: any port
    std::string user, secret;    // Password: user name and password. Token: secret only. ArchiveKeys: access key and secret.
    bool allowUnencrypted = false;
};
// Replaces the whole table. Thread-safe; takes effect for requests built afterwards.
void setSignIns(std::vector<SignIn> signIns);
// The sign-in a request to scheme://host:port may carry, after the coverage and encryption rules; none otherwise.
std::optional<SignIn> signInFor(const std::string& scheme, const std::string& host, unsigned port);
// True when a sign-in is saved for this host at all, whatever the scheme (to tell "refused, none saved" from "may not be sent").
bool hasSignIn(const std::string& host, unsigned port);
// "Authorization: <value>\r\n" for HTTP.
std::string authorizationHeader(const SignIn&);
// Sent with the first request (tokens, archive.org keys) or only after a Basic challenge (passwords).
bool sentAtOnce(const SignIn&);
// A server refused for lack of a sign-in (rejected == false) or refused the one that was sent (rejected == true).
struct SignInNeeded : std::runtime_error {
    std::string host;
    bool rejected, basic; // basic: the server offered HTTP Basic
    SignInNeeded(const std::string& host, bool rejected, bool basic);
};
```

`SignInNeeded::what()` is exactly `"Sign-in needed for <host>. Add it in Settings, then resume."` when not rejected and `"The sign-in for <host> was not accepted."` when rejected. It is not an `archive::NetworkError`, so nothing retries it.

  - Coverage: a `huggingface.co` token is returned for `https` `huggingface.co` and `hf.co`, not for `cdn-lfs.hf.co`, `xyz.huggingface.co` or `example.org`. A `github.com` token covers `github.com` and `api.github.com`, not `objects.githubusercontent.com`. `archive.org` keys cover `archive.org`, `ia800100.us.archive.org` and `www.archive.org`, not `web.archive.org`, not `notarchive.org`, not `archive.org.evil.test`. Host comparison ignores case.
  - Ports: a password saved for `example.org` port 8443 is returned for 8443 only; port 0 matches any port.

### Task 2: HTTP: attach, challenge, redirects

**Files:** Modify `src/http.cpp`, `src/platform/http_winhttp.inc`, `src/platform/http_curl.inc`, `tests/engine_server.py`, `tests/engine.cpp`.

**Interfaces — Consumes:** Task 1. **Produces:** no new public functions; `get`, `fetch`, `post`, `loadDirectLink` and `archive::download` behave as below.

- [ ] **Step 1: Server modes** in `tests/engine_server.py`. The server already listens on `127.0.0.1`; the same port is reachable as `localhost`, which the engine treats as a different host. `/stats` gains `auth`: a map from the request's `Host` header name (without port) to the list of `Authorization` values received there since `/reset`.

| Mode | Behavior |
|---|---|
| `basic` | Needs `Authorization: Basic` for `user` / `pass`; otherwise 401 with `WWW-Authenticate: Basic realm="test"`. With it, behaves like `etag` (ranges, strong ETag) |
| `bearer` | Needs `Authorization: Bearer tok`; otherwise 401 with `WWW-Authenticate: Bearer`. With it, like `etag` |
| `redirect-out` | Needs Bearer `tok`; answers 302 to the same path in mode `etag` on the other host name (a request to `127.0.0.1` goes to `localhost` and the reverse) |
| `redirect-back` | 302 to mode `bearer` on the same host name |
| `redirect-loop` | 302 to itself |
| `forbidden` | 403 always |

- [ ] **Step 2: Failing engine tests** (10 MiB, 4 connections unless stated; each sets the table with `archive::setSignIns` and clears it afterwards with a scope guard):
  1. `basic`, no sign-in: `run` throws `archive::SignInNeeded` with `rejected == false`, `basic == true`, host `127.0.0.1`.
  2. `basic-ranges`: Password `user`/`pass` for `127.0.0.1`: file correct, `stats.maxConcurrent >= 2`; then with `pauseAt = 3 MiB` and a second run: file correct, `stats.bytes < 15 MiB`.
  3. `basic-wrong`: Password `user`/`nope`: throws `SignInNeeded` with `rejected == true`; the server received at most 2 requests with that header.
  4. `bearer`, Token `tok` for `127.0.0.1`: file correct, and every request the server saw on `127.0.0.1` carried `Bearer tok`.
  5. `redirect-out`, Token for `127.0.0.1` only: file correct; `stats.auth` for `localhost` is empty or has no entry.
  6. `redirect-back`, Token for `127.0.0.1`: file correct.
  7. `redirect-loop`, Token for `127.0.0.1`: throws a `NetworkError` that is not retryable, after no more than 11 requests.
  8. `forbidden`, no sign-in: throws an error whose text starts with `HTTP 403` and is not a `SignInNeeded`.
  9. A host with no sign-in and mode `etag`: `stats.auth` is empty (nothing is ever sent unasked).
  10. `archive::fetch` of `/stats` through a `bearer`-protected path variant is not needed; instead `fetch` on `basic/1024/file.bin` with the Password saved returns `file == true` (loaders sign in too).
- [ ] **Step 3: Run.** Expected: compile passes; tests 1 to 8 fail.
- [ ] **Step 4: Implement.**
  - Both transports: a way to build a `Request` that does not follow redirects and does not throw for a 3xx answer, exposing the status and the `Location` header (WinHTTP: `WINHTTP_OPTION_REDIRECT_POLICY_NEVER` and `WINHTTP_QUERY_LOCATION`; curl: `CURLOPT_FOLLOWLOCATION` 0 and the stored `location` field). A 401 exposes whether `WWW-Authenticate` offers Basic.
  - In `http.cpp`, one function builds a request for a URL: when `hasSignIn` is false for its host it does exactly what `get` does today. Otherwise it takes the manual path: look up `signInFor(scheme, host, port)`; attach the header when `sentAtOnce`, or after a 401 with a Basic challenge for a password (one repeat of the request); on a 3xx, resolve `Location` against the current URL, refuse `https` to `http`, count the hop (limit 10, then a non-retryable `NetworkError`), and loop with a fresh lookup for the new host (which may have none and then takes today's path for the rest).
  - 401 anywhere: `SignInNeeded(host, rejected, basic)`, with `rejected` true when a sign-in was sent on that request. This replaces today's `statusError` text for 401 only; 403 keeps today's message.
  - `Request::url()` and `host()` keep returning the final address after redirects on both paths, so the probe, mirror and range code are unchanged.
  - The existing retry loop in `get` does not retry `SignInNeeded`.
  - `Authorization` values are never passed to a log call.
- [ ] **Step 5: Build and run** on both platforms; run `engine` five times on each. Expected: all pass, including every earlier engine case.

**Interfaces — Produces** (namespace `lite`):

```cpp
struct SavedSignIn {            // one row of the list; the secret is not kept here once handed over
    archive::SignIn value;      // secret empty when it could not be read
    bool remembered = false;    // written to the credential store
    bool available = true;      // false: listed in settings.ini but its secret could not be read
};
bool signInStoreUsable();                               // wxSecretStore::GetDefault().IsOk()
std::vector<SavedSignIn> signIns();                     // the current list, session-only ones included
// Adds or replaces the sign-in for value.host (and port); writes the store when remember and the store is usable.
void saveSignIn(const archive::SignIn& value, bool remember);
void removeSignIn(const std::string& host, unsigned port);

void loadSignIns();
```

The list in `settings.ini` is one key `signIns` holding JSON: an array of `{"host", "port", "kind", "user", "unencrypted"}` with no secret.
